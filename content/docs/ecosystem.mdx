Drizzle 的核心很小，周围围绕着一组官方工具与社区集成。理解它们各自的职责，可以避免把「迁移工具」「校验库」「GUI」误当成 ORM 的一部分。

## 官方工具

| 工具 | 职责 |
| --- | --- |
| `drizzle-orm` | 查询构建器、schema 定义、类型推导 |
| `drizzle-kit` | 迁移生成与执行、push/pull、Studio 启动 |
| Drizzle Studio | 本地数据库浏览与编辑界面 |
| `drizzle-seed` | 可复现的种子数据生成 |
| `drizzle-zod` | 从 schema 生成 Zod 校验器 |
| `drizzle-valibot` | 从 schema 生成 Valibot 校验器 |
| `drizzle-arktype` | 从 schema 生成 ArkType 校验器 |

### drizzle-seed

`drizzle-seed` 可以根据 schema 生成结构合法的测试数据，并通过固定种子保证可复现：

```bash
bun add -d drizzle-seed
```

```ts
import { seed } from 'drizzle-seed';
import { db } from './db';
import * as schema from './db/schema';

await seed(db, schema).refine((f) => ({
  users: {
    count: 50,
    columns: {
      name: f.fullName(),
      email: f.email(),
    },
  },
  posts: {
    count: 200,
  },
}));
```

具体生成器与 refine 语法会随版本变化，请以[官方文档](https://orm.drizzle.team/docs/seed-overview)为准。

### schema 校验

以 `drizzle-zod` 为例，同一份 schema 可以同时服务于数据库与 API 输入校验：

```ts
import { createInsertSchema, createSelectSchema } from 'drizzle-zod';
import { users } from './db/schema';

export const insertUserSchema = createInsertSchema(users, {
  email: (schema) => schema.email(),
});

export const selectUserSchema = createSelectSchema(users);
```

这样可以避免「数据库 schema」与「请求校验 schema」各写一份而逐渐漂移。

## 与框架和平台集成

Drizzle 不绑定框架，因此集成方式通常是「在框架的数据库初始化位置接入驱动」：

- **Astro**：在 `src/db` 中初始化，按需在端点或服务端组件中调用。
- **Next.js**：在服务端模块或 Route Handler 中复用连接池。
- **Hono / Cloudflare Workers**：从 `env` 获取 D1 绑定，按请求创建轻量客户端。
- **Bun / Deno**：直接使用内置 SQLite 或 postgres.js。
- **Better Auth 等认证库**：许多社区库提供 Drizzle 适配器，可直接复用同一份 schema。
