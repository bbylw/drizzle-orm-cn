title: 性能
description: 从列裁剪、索引、N+1、预编译到连接池，理解 Drizzle 应用中的常见性能杠杆。
---

Drizzle 本身只负责生成 SQL 与类型，应用性能最终取决于**查询质量、索引设计与连接管理**。下面这些杠杆，比任何 benchmark 数字都更值得关注。

## 只查询需要的列

```ts
// 不推荐：宽表上浪费带宽与解析时间
const users = await db.select().from(users);

// 推荐：按页面需要裁剪
const users = await db
  .select({ id: users.id, name: users.name })
  .from(users);
```

列裁剪不仅减少传输量，也能避免把大字段（JSON、文本）带入内存。

## 让索引真正生效

- 为常用过滤列与排序列建立索引，复合索引遵循最左前缀原则。
- 外键列默认不会自动建索引（PostgreSQL），需要显式添加。
- 唯一约束本身会创建索引，不要重复添加。
- 大表建索引时考虑并发创建，避免长时间锁表。
- 定期用 `EXPLAIN ANALYZE` 检查执行计划，而不是凭直觉优化。

```ts
import { sql } from 'drizzle-orm';

const plan = await db.execute(
  sql`explain analyze select * from posts where author_id = ${authorId} order by created_at desc limit 20`,
);
```

## 避免 N+1 查询

典型反模式：先查列表，再对每一条发起一次关联查询。

```ts
// 反模式：N + 1
const posts = await db.select().from(posts).limit(20);
for (const post of posts) {
  const author = await db.select().from(users).where(eq(users.id, post.authorId));
}
```

改为 join 或关系查询：

```ts
const rows = await db
  .select({
    postId: posts.id,
    title: posts.title,
    authorName: users.name,
  })
  .from(posts)
  .innerJoin(users, eq(posts.authorId, users.id))
  .limit(20);
```

```ts
const rows = await db.query.posts.findMany({
  limit: 20,
  with: {
    author: { columns: { name: true } },
  },
});
```

## 分页策略

`offset` 在深分页时成本较高，因为数据库仍需扫描并丢弃前面的行。数据量大时改用键集分页（keyset pagination）：

```ts
const rows = await db
  .select()
  .from(posts)
  .where(lt(posts.createdAt, lastSeenCreatedAt))
  .orderBy(desc(posts.createdAt), desc(posts.id))
  .limit(20);
```

键集分页需要稳定且唯一的排序键（通常追加主键）。

## 预编译语句

对高频、结构固定的查询，可以复用预编译语句：

```ts
import { sql } from 'drizzle-orm';

const findUserById = db
  .select()
  .from(users)
  .where(eq(users.id, sql.placeholder('id')))
  .prepare('find_user_by_id');

await findUserById.execute({ id: 1 });
await findUserById.execute({ id: 2 });
```

预编译的支持程度取决于驱动与运行时；无服务器 HTTP 驱动通常每次请求新建连接，收益有限。

## 批量写入

多行插入应合并为一条语句，而不是循环调用：

```ts
await db.insert(events).values(
  batch.map((event) => ({
    type: event.type,
    payload: event.payload,
  })),
);
```

注意单条语句的参数上限与事务大小。超大写入建议分批提交，并根据数据库调整批次大小。

## 连接池与运行时

- **Node.js 长驻服务**：复用同一个 `Pool`，按数据库上限设置 `max`。
- **无服务器函数**：避免每个请求新建连接却不释放；使用平台连接池或 HTTP 驱动。
- **边缘运行时**：选择基于 HTTP 的驱动，减少 TCP 建连与冷启动开销。
- **脚本任务**：结束后关闭客户端，避免进程无法退出。

## 日志与观测

开发环境打开 SQL 日志：

```ts
export const db = drizzle({ client, logger: true });
```

生产环境建议：

- 记录慢查询（语句、耗时、参数数量），而不是所有 SQL。
- 对错误与超时设置告警。
- 定期抽样 `.toSQL()` 输出，确认查询形态符合预期。
- 不要在生产日志中记录敏感参数。

## 构建体积与冷启动

- 只导入实际使用的模块与运算符。
- 在边缘环境测量打包后的体积，避免无意引入 Node.js 专用模块。
- 将数据库客户端初始化放在请求作用域之外（但注意连接对象的生命周期）。
- 对冷启动敏感的路径，优先选择轻量驱动与 HTTP 连接。

<Callout type="warn" title="不要只看 benchmark">
不同 ORM 的基准测试往往针对特定查询与数据规模。请用自己的真实查询、真实数据量与目标运行时做对比，并关注尾延迟而非平均值。
</Callout>
